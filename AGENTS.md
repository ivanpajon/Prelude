# Agent instructions

This repository is a Next.js 16 starter in a pnpm and Turborepo workspace. One oRPC contract with ArkType schemas serves RPC, REST with an OpenAPI document and Scalar reference, and native MCP tools. The website is localized in English and Spanish with next-intl and works as a PWA with Serwist.

## Packages

- `apps/web` (`@repo/web`): the Next.js App Router website and the API, OpenAPI, MCP, and health routes. `apps/web/src/site.ts` holds the site name and repository URL.
- `packages/contracts` (`@repo/contracts`): API contracts and schemas. Add each feature's contract to `src/index.ts`.
- `packages/api` (`@repo/api`): the procedures that implement the contracts, mounted in `src/router.ts`.
- `packages/i18n` (`@repo/i18n`): English and Spanish message catalogs in `src/messages/{en,es}`.
- `packages/ui` (`@repo/ui`): shadcn components on Base UI, Tailwind 4 styles, and `cn`.
- `packages/temporal` (`@repo/temporal`): Temporal dates and times with a browser fallback.
- `scripts/` holds the development launcher and the repository commands; `tests/` holds the Playwright suites. Vitest tests sit next to the code they test.

## Commands

Run from the repository root with Node 26 (`.node-version`) and pnpm 12.6.0.

- `pnpm dev`: Next.js on port 3000 with the MCP Inspector on 6274 and 6275. `pnpm dev:app` skips the Inspector.
- `pnpm check`: Biome and strict TypeScript. `pnpm fix` applies Biome's formatting and safe fixes.
- `pnpm test`: Vitest unit and component tests.
- `pnpm verify`: check, tests with coverage, development and production browser tests, and the build cache check (4-10 minutes). Run `pnpm exec playwright install chromium` once first.
- `pnpm test:stack`: the Docker production and development stacks (5-15 minutes, needs Docker).
- `pnpm mcp:check`: list the tools of a running MCP endpoint.
- `pnpm customize`: rename the root package and the workspace scope.

Before committing, run `pnpm check` and `pnpm test`. Also run `pnpm verify` when a change affects pages, routes, the build, or the service worker, and `pnpm test:stack` when it affects Docker files. Stop `pnpm dev` before `pnpm verify`: both use the development output and lock.

## Conventions

- Biome is the only linter and formatter. Do not add ESLint or Prettier.
- Commits follow Conventional Commits (`feat:`, `fix(api):`, `docs:`). Hooks run Biome on staged files and Commitlint on the message; do not skip them.
- Dependencies use exact versions (`saveExact` in `pnpm-workspace.yaml`). Commit `pnpm-lock.yaml` and install with `pnpm install --frozen-lockfile`. Renovate opens the update pull requests (`renovate.json`).
- pnpm comes from `packageManager` in `package.json`; use pnpm only, never npm or yarn.
- Workspace packages share one private scope (`@repo` in the template; `pnpm customize` renames it). Import across packages by package name, such as `@repo/ui/components/button`.
- Put user-facing text in both catalogs of `@repo/i18n`, in natural English and Spanish.
- Add an API feature as a contract in `@repo/contracts` and a procedure in `@repo/api`; OpenAPI and MCP pick it up. See [OpenAPI](docs/openapi.md#add-or-change-a-procedure).

## Generated files

Do not edit these by hand:

- `pnpm-lock.yaml`: change it only through pnpm.
- `apps/web/public/sw.js` and its map: generated by Serwist during `pnpm build`.
- `next-env.d.ts`, `.next/`, `.turbo/`, `coverage/`, `playwright-report/`, and `test-results/`: build and test output, ignored by Git.
- The Next.js rules block in `apps/web/AGENTS.md`: written by `next dev`.
