# Customize package names

`@repo` is the default workspace scope. It is private to the repository and does not require an npm organization. Keeping it is valid, including when the repository or project folder has another name.

To customize package names, stop development and run from your generated project's root:

```sh
pnpm customize --name my-app --scope "@acme" --dry-run
pnpm customize --name my-app --scope "@acme"
```

Use the Node and pnpm versions pinned by the project, and complete the initial `pnpm install --frozen-lockfile` first. The customizer uses Node built-ins without adding dependencies. Git must be installed and the project root must have its own Git repository; create-next-app and GitHub template checkouts already provide one. For a downloaded ZIP, run `git init` first.

## Options

| Option | Behavior |
| --- | --- |
| `--name my-app` | Change the root `package.json` name to an unscoped lowercase package name. |
| `--scope @acme` | Change all private workspace packages to this lowercase npm scope. Include the `@`. |
| `--dry-run` | Print proposed file changes without writing, installing, or validating. |
| `--help` | Show usage. Calling `pnpm customize` without name/scope options also shows help. |

Omitting `--scope` keeps the current scope, initially `@repo`. Omitting `--name` keeps the root package name. For example, `pnpm customize --name my-app` keeps imports such as `@repo/ui/components/button` intact. Quote scope arguments as shown so the command also works in PowerShell.

The command discovers scoped, private packages under `apps/*` and `packages/*`, matching the template's workspace boundaries. All must share one scope. If you change that architecture, update the customizer before using it.

## What changes

For `--scope @acme`, `@repo/ui` becomes `@acme/ui`, and imports such as `@repo/ui/components/button` become `@acme/ui/components/button`. The same change applies to every workspace package, including the application. Changes cover package dependency keys, Next.js transpilation, TypeScript paths, shadcn aliases, package filters in commands, React Doctor configuration, test configuration, and documentation.

Only exact discovered workspace package names and their subpaths change. Other packages in the same npm scope are left alone. Git supplies the list of tracked and untracked, nonignored files; generated output, ignored local files, symlinks, and nontext assets are skipped. The lockfile is regenerated by pnpm rather than edited as text. Existing edits are preserved outside the renamed references; review and commit the resulting diff yourself.

The command then:

1. Runs `pnpm install --no-frozen-lockfile` to refresh the lockfile and workspace links.
2. Applies Biome formatting/import organization to changed supported files.
3. Runs `pnpm check` and `pnpm test`.

Production builds and browser tests remain available through `pnpm verify`. The customizer does not rename the folder, Git repository or remote, application metadata, manifest, icons, or visible Prelude branding.

## Reruns and errors

The existing scope is discovered from workspace manifests, so a second rename works without resetting to `@repo`. Repeating the same values makes no further text changes but still installs and validates. Invalid arguments, inconsistent workspace scopes, or conflicting dependency names fail before writes.

If installation or validation fails, the command exits unsuccessfully and leaves the changes visible for inspection. Fix the reported problem and rerun the same command. No commit is created automatically, and the command does not discard existing work.
